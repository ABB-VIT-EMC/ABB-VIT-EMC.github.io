Writing a Test Case in Cartamodello Format¶

The SAARTO framework relies on Cartamodello (.cm) files to define Test Cases (TC) and Structural Elements (SE). These hybrid files bridge static configuration (TOML) with executable test logic (Python + Jinja2 templates).

Overview¶

There are two (+1) type of Cartamodello files:

  1. Test Case (.cm) – defines the test logic, parameters, and required instruments.

  2. Structural Element (.cm) – defines reusable building blocks for instruments and libraries.

  3. Config Recipe (.cmconf) – defines reusable configuration snippets for test cases, such as common parameter sets or instrument groups.

For ease of creration, refer to the Cartamodello VS Code extension, which provides syntax highlighting, autocompletion, and validation for Cartamodello files.

Test Case Creation¶

Let’s create a test case that commands a generator and reads a multimeter.

  1. You create test_voltage.cm and manually type out the ### TOML-BLOCK-START: TEST_CASE and ### TOML-BLOCK-END: TEST_CASE markers.

  2. You define [instrument] and explicitly write generator = “…” and dmm = “…”, the user may choose to fill in the actual instrument names right here to serve as default selections.

  3. You create python block for dependencies ### PYTHON-BLOCK-START: TC_DEPENDENCIES and put everything that’s needed to be imported inside.

  4. You type out the ### PYTHON-BLOCK-START: TEST_STEPS markers and ### PYTHON-BLOCK-END: TEST_STEPS.

  5. You write the Python code: {{ instrument.generator }}.set_voltage({{ parameter.static.v_target }}) … .

The Risk: You must manually scroll up and ensure v_target exists under [parameter.static]. If you forget, the test fails to compile later.

### TOML-BLOCK-START: TEST_CASE
[instrument]
generator = ""
dmm = "fluke_dmm"

[parameter.static]
v_target = 10
t_delay = 2
### TOML-BLOCK-END: TEST_CASE

### PYTHON-BLOCK-START: TC_DEPENDENCIES
from matta import tui
import time
### PYTHON-BLOCK-END: TC_DEPENDENCIES

### PYTHON-BLOCK-START: TEST_STEPS
    {{ instrument.generator }}.set_voltage({{ parameter.static.v_target }})
    {{ instrument.dmm }}.read_voltage()
    time.sleep({{ parameter.static.t_delay }})
### PYTHON-BLOCK-END: TEST_STEPS

Note

Since the python block goes into a function, an indentation is required.

Structural Element Creation¶

A Structural Element (SE) defines how SAARTO communicates with hardware. SAARTO’s fetch pipeline searches these files for the INSTRUMENT_DEFINITION block. By architectural requirement, every SE must have a class and name.

  1. You create fluke_dmm.cm.

  2. You type the TOML block [fluke_dmm].

  3. You must remember SAARTO rules and manually add class = “dmm” and name = “dmm_1”. If omitted, the SE library cannot parse the file.

  4. You add your custom attributes like baudrate.

  5. You type out ### PYTHON-BLOCK-START: SE_SETUP and write the connection logic, ensuring every variable explicitly matches your TOML.

[fluke_dmm]
class = "dmm"       # device class
name = "dmm_1"      # the device name that will appear when the code is generated,
                    # if many of the same device type exist, the name must be different
baudrate = 9600     # Custom parameter
